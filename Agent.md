# Agent rules: classifying wallpapers

## Layout

- `full-size/`: the wallpapers, named `NNN-description.ext`
- `previews/` and `README.md`: generated by `./build-readme.sh`, never edited by hand
- New wallpapers get dropped in a loose folder (`temp/`, `tmp/`) or the repo root, usually named `wallhaven-xxxxxx.ext`

## Naming

- `NNN-description.ext`, numbered from `001` with no gaps. Pad to 3 digits (4 if the set ever passes 999).
- The description is short, lowercase and hyphenated, and comes from actually looking at the image.
- Use the source title or character names when recognizable (`akira-kaneda-bike`, `frieren-snowy-windmill`); otherwise describe what is in it (`red-lit-underpass`).
- Never prefix the name with a color label (`NNN-red-...`). A color word is fine when it describes the image (`magenta-sky-rooftop`).
- Keep the original extension. Never convert files.

## Color groups

Every wallpaper belongs to exactly one group. Groups run in this order:

red → orange → beige → yellow → green → cyan → blue → purple → pink → white → gray → black

- Judge the group **by eye**: it is the color you notice first, not the pixel average.
- A dark or black image with one strong color accent goes in the accent's group (red skull on black → red, pink flame skull on black → pink, yellow doorway in a dark corridor → yellow).
- An image with no real accent goes in white, gray or black by its overall tone.
- Desaturated warm tones (paper, sand, peach, ink sketches on cream) are beige; brown is orange.

## Order inside a group

1. **Background tone first:** bright or light backgrounds, then mid-tone, then dark or black.
2. **Hue second, within each tone tier:** drift from the previous group's side toward the next group's side.
   - red: pink-red → orange-red
   - blue: cyan-blue → violet-blue
   - pink: purple-pink → red-pink
   - and so on for the other color groups
3. **White, gray and black** have no hue axis: sort lightest to darkest.
4. `pure-black` is always the very last wallpaper.

Measured brightness and hue can help suggest an order, but the final call is by eye. Measurements misjudge saturated backgrounds (a bright red reads as mid-tone), mostly-black images and multicolor art. No sorting script is kept in the repo.

## Adding new wallpapers

1. **Check for duplicates** against `full-size/` and among the new files:
   - exact copies: compare file hashes
   - resized or re-encoded copies: compare small thumbnails by eye
   - Mostly-black images look alike to any fingerprint, so confirm visually. Report duplicates instead of silently dropping them.
2. **Look at every new image** (contact sheets of thumbnails work well), then name it and pick its group.
3. **Slot it into its group** following the order rules above, and renumber the whole set.
   - Use `git mv` for tracked files.
   - Rename through temporary names so numbers never collide.
4. **Delete the drop folder** once it is empty.
5. **Run `./build-readme.sh`** to regenerate `previews/` and the README gallery.
6. **Check the result** with a contact sheet of `previews/` in order: the colors should run red → black with no stragglers.
7. **Stage the changes** and leave the commit to the user unless asked.
